8: A=1. OBJECTIVES
9: A=• Distribute brand partner gift codes to players through a controlled and validated system.
10: A=• Ensure the gift code distribution is secure, non-duplicated, and resistant to exploits.
11: A=• Players receive brand gift codes via the in-game system mail (update/notification section).
14: A=2. BACKGROUND
15: A=Database Constraints | C=• The current system does not support a global database for shared values.
• The database API only provides concurrency protection on DataStore entries, where each write operation must be tied to a unique UID.
• The current database system does not provide sufficient tracking capabilities, making it difficult to monitor how many giftcodes have been bypassed or remain unused.
16: A=Giftcode Storage Limitations | C=• The database does not support storing large volumes of giftcodes efficiently. As a workaround, giftcodes must be stored in CSV files.
• However, approximately 10,000 giftcodes equal ~1MB, which requires the client to download the entire file. As a result, storing 4 million giftcodes would require users to download an additional ~35MB.
17: A=How Users claim Giftcodes | C=The system supports two giftcode claim methods:
      1. Auto-Grant on Player Join: Giftcodes are automatically granted when a player joins the game. This method has a potential abuse risk, as users may create and spam cloned accounts to receive giftcodes.
      2. Claim via Event Milestone Completion: Giftcodes are granted after the player completes a specific event milestone.
20: A=3. DESIGN PROPOSAL
21: A=Overview
22: A=• The system uses a single DataStore UID as a global counter (referred to as UID AAA) to control giftcode distribution order and prevent duplication.
23: A=• Each giftcode is assigned sequentially based on the global counter value.
24: A=• Failure Handling:
      • If any read or write operation fails at any step, the process is immediately aborted.
      • No partial state is retained.
      • The user must rejoin the match to retry receiving a giftcode.
25: A=• This approach ensures:
      • No duplicate giftcodes are assigned.
      • Sequential and controlled distribution.
      • Safe recovery from failure without inconsistent data states.
